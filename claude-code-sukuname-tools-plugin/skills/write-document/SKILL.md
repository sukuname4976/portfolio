# write-document スキル

Markdown ファイルとして用意されるドキュメントを、記法の規約に沿って作成・編集する

## 基本方針

- 不明点は必ずユーザーに確認する、想像で補完しすぎない
- 最小限の変更から始めて、フィードバックを受けてステップバイステップで追記する

## 手順

1. 対象の Markdown ファイルを確認
2. 作成・編集すべき内容が不明確な場合、ユーザーに対して書く内容を提案・質問
3. markdownlint ルールと表現ルールを確認する
4. 最小限の内容で記述
5. `npx markdownlint-cli2 <file>` で、ファイルが markdownlint ルールに従っていることを確認
6. ファイルが全ての表現ルールに従っていることを確認
7. ルール違反箇所を修正
8. ユーザーにサマリーを提示し、フィードバックを受けたら 4 に戻る

## markdownlint ルール

`.markdownlint-cli2.jsonc` を参照

- `gitignore: true` : .gitignore と同じ除外
- `MD041: false` : 先頭 h1 チェック無効（スキル等で @ 参照を使うため）
- コード例など改行すると意味が変わるものは、コメントで囲んでルールを無視する

  ```markdown
  <!-- markdownlint-disable MD013 -->
  長いコマンド例...
  <!-- markdownlint-enable MD013 -->
  ```

## 表現ルール

- 情報はリスト(箇条書き・番号付き)を積極的に採用して整理する
- リスト項目の末尾には句点を付けない
- 記号は原則半角にする(かっこ・セミコロンなど)
  - ただし句読点(、。)・中点(・)・波ダッシュ(〜)は全角を使う
- 数字は必ず半角にする
- 半角英数字・記号と全角文字の間には半角スペースを入れる(例: `Go 言語`)
  - ただし句読点の直後は不要(例: `実装する。Go で〜`)
