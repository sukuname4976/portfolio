# ポート方針

バックエンド API (`apis/*`) のポート割り当て方針。
フロントエンド (`clients/web`) は本方針の対象外で、Next.js のデフォルト port `3000` を本番・開発とも使う。

## 本番と開発の違い

ポート以外にも以下の違いがあることを前提に扱うこと。

- 開発サーバー (`make dev` / `nx serve`) は開発向け機能 (ホットリロード等) を有効にして起動する一方、本番向けの最適化は行われない
- 本番相当の動作を試すには `make up` で本番向けに最適化した状態で起動する
- 本番と開発で挙動が異なる可能性があるため、リリース前の動作確認は `make up` 側で行う

## 方針 (API)

- 本番: 全サービスを port `8000` に統一
  - クライアント側 (clients/web 等) やインフラ側が「サービスごとに違うポート」を意識せずに済むようにする
  - 本番は各サービスが独立したコンテナ・ホストで動くため、同一ポートでも衝突しない
- 開発: 衝突回避のためサービスごとに固有ポートを割り当てる
  - 各サービスの開発ポートはルート `README.md` のディレクトリ構造に記載
  - 開発時は同一ホストで複数サービスを並行起動するため、サービスごとに異なるポートを使う

## 実装上の分担

- 本番値 `8000` を持つ箇所
  - `config.go` の default (env 未指定時のフォールバック)
  - `Dockerfile` の `EXPOSE`
  - `docker-compose.yaml` (本番イメージ) の `ports` と `environment.PORT`
  - `Makefile` の `up` ターゲット (env 未指定のまま default `8000` が効く)
- 開発値 (各サービス固有、ルート `README.md` 参照) を持つ箇所
  - `Makefile` の `dev` ターゲット (`PORT=xxxx air -c .air.toml` で明示指定)
  - `project.json` の `serve` ターゲット (nx serve 経由)
  - `server-behavior-test` スキルの curl 先 (開発サーバーに対して動作確認する想定のため)
  - `.devcontainer/go/devcontainer.json` の `forwardPorts`
- 本番値・開発値の両方を併記する箇所
  - 各サービスの `IF/openapi.yaml` の `servers[]` (本番値を先頭、開発値を後続)

## 新サービス追加時

- 本番ポートは `8000` で揃える
- 開発ポートは既存と衝突しない値を割り当て、ルート `README.md` に追記する
