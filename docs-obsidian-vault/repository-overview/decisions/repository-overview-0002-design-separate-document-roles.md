# repository-overview-0002. 情報の置き場所を役割で分ける

## 決定事項

### 判定

情報の置き場所は次の順で決める。

1. **書かなくても正しい結果に落ち着くか** → 落ち着く → どこにも書かない
2. **必要になったときに引くきっかけがあるか** → ある → ADR、README、コード
3. どちらでもない → `agents-base.md`

1 では、強制の有無ではなく結果を見る。CI は強制するがマージ時なので手戻りが
出る。lint は一部しか直さない。どちらも「落ち着かない」と判定する。

### ビューの位置づけ

- ADR 以外のドキュメントはすべて ADR のビューとして扱う
- ビューには、人間やエージェントにとって役立つものを適宜書いてよい。
  長さも内容も、読み手が便利かどうかで決める
- 判断の理由や適用の条件は、ADR へのリンクで簡潔に済ませるとよい。決まりごとを
  長々と書き写すと保守が続かず、どちらが正か分からなくなる

### 役割

- `agents-base.md` : エージェントが毎回自動で読む。定位のための概要と、
  行動の起点だけを置く。ここだけは分量を絞る
- README : 人間が作業するための案内。手順やコマンドなど
- ADR : 判断と理由。エージェントは `find-adr`、人間は README のリンクで辿る
- コード・設定 : 事実の正。バージョン、依存、パスはここだけが持つ

### `agents-base.md` の書式

- h1 はプロジェクト名とする
- `## 概要` : 何のプロジェクトかと、技術の名前と役割を書く。バージョンや
  パス一覧のように他に正があるものは書かない
- `## 作業の進め方` : 読み込みの通知と、着手前や完了前にやることを書く
- `## 作業の進め方` の先頭に読み込みの通知を置く。ファイルごとに自分の
  パスを名乗らせ、どの階層まで読み込まれたかを分かるようにする
- 同じ役割のファイルが複数あるときは、並べて突き合わせてから確定する

## コンテキスト

`agents-base.md` は `AGENTS.md` の連鎖でエージェントのコンテキストへ毎回
自動的に読み込まれる。ADR や README は読み込まれない。

その `agents-base.md` に何を書くかの基準が無く、内容がばらついていた。

- `api-bff` は「Go 1.21」「標準ライブラリ (net/http)」と書いていたが、
  実際は Go 1.25 で ogen による生成に変わっていた
- 8 ファイルのうち 5 つは h1 と 1 行だけで、実質何も書かれていなかった
- `infra-terraform` には apply の規範が本文で書かれており、ADR に移すと
  二重管理になる状態だった

書き写した情報が更新されずに残り、エージェントは誤った前提で作業を始める。

## 却下事項

### 判定

- **ツールで強制できるかで判定する**: 手段が明確で判定も速いが、強制の
  タイミングと範囲を見ていない。CI はマージ時にしか止めず、lint は一部しか
  直さないのに、どちらも「強制できる」に当てはまってしまう

### ビューの位置づけ

- **ビューには参照と短い説明だけを残す**: 復唱が無くなり、ADR を書き換えた
  ときの同期漏れも起きないが、手順を知るためだけに ADR を開くことになる。
  README が索引にしかならず、人間にとっての利便性が失われる
- **ビューに書ける内容を列挙で限定する**: 何を書いてよいかが一目で分かるが、
  列挙から漏れたものを書けなくなる。読み手にとって便利かどうかで決めるほうが
  実態に合う

### 役割

- **`agents-base.md` に技術スタックとディレクトリ構成を書く**: 定位が速く
  なるが、`go.mod` やコードと二重管理になり、更新されずに腐る。実際に Go の
  バージョンが古いまま残っていた
- **規範を `agents-base.md` に列挙する**: 検索しなくても目に入るが、件数に
  比例して毎回のコンテキストを消費する。`find-adr` で引ける
- **各プロジェクトの `agents-base.md` に ADR への案内を書く**: どの階層から
  入っても目に入るが、8 箇所の重複になる。ルート 1 箇所で全セッションに届く
- **README をエージェントにも読ませる**: 置き場所が 1 つで済むが、手順や
  コマンド一覧まで毎回読み込むことになる

### 書式

- **読み込みの通知をルートだけに置く**: 出力が 1 行で済むが、作業の途中で
  読み込まれたプロジェクト側のファイルに気づけない
- **読み込みの通知を出さない**: 出力が静かになるが、連鎖が切れて読み込まれて
  いない状態に気づけない

## 前提と見直し条件

- `agents-base.md` が `AGENTS.md` の連鎖で自動的に読み込まれることを前提と
  する。読み込みの通知が出なくなったとき、連鎖の構成を見直す
- pre-commit hook が未導入であることを前提とする。Issue #25 で導入されたとき、
  `make prepare` を書く必要があるかを見直す
- `language` 設定で日本語の出力が維持されることは未検証である。維持されて
  いることを確認できたとき、`agents-base.md` の出力言語の指示を消す
- lint と CI が既存の規則を強制していることを前提とする。強制の対象から外れた
  規則が出たとき、その置き場所を見直す
